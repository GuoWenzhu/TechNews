## 2. Brotli 漏洞（CVE-2026-111497）演进为"HTTP2Shell"：影响面从 Node.js 扩大到整个 HTTP 生态

- **发布时间**：Node.js 10-21 首次披露；10-23 影响面扩大至多语言与 HTTP 服务组件（Aikido 综合 10-23 发布、10-24 更新）
- **来源**：Aikido Security、Node.js、Python 安全通告（经 Aikido 汇总）
- **核心内容**：Google Brotli 压缩库存在越界写入漏洞（CVE-2026-111497）：解码攻击者控制的 Brotli 数据可导致内存泄露或任意代码执行（"node2shell"）。时间线：10-21（周三）Node.js 首先披露；10-22（周四）Python 方面确认多个包同样受影响；10-23（周五）确认为影响扩展到"使用 HTTP 的主要语言与服务应用"（HTTP2Shell），波及面包括 Envoy 等，补丁最初不全。截至 10-23 晚，libbrotli、Python、C++、Node.js、bun、Envoy 等已有补丁；Apache 与 Nginx 默认不解码 Brotli。OpenAI 表示其今年 2 月就发现了该底层缺陷并修复了 Brotli 源码，当时未意识到其安全影响，现已另行发布公告。临时建议：无补丁的组件暂禁用 Brotli 解码。
- **背景/影响**：一个压缩库的内存缺陷在五天内演变为跨 Node/Python/C++/服务网格的全生态事件，再次暴露 HTTP 内容编码路径作为"共享攻击面"的系统性风险；对自建服务与 Agent 网关类组件，需立即核对 Brotli 解码依赖与版本。
- **原始链接**：
  - https://www.aikido.dev/blog/python-packages-vulnerable-node2shell-brotli-cve-2026-111497
  - https://news.ycombinator.com/item?id=50219177

## 5. 中期选举前的 AI 立场测试：Grok 联网时偏共和党、OpenAI 模型权重内偏民主党，Grok API 藏约 1,240 个隐形 token

- **发布时间**：2026-10-24 15:00 UTC（TechCrunch）
- **来源**：TechCrunch（研究者 Parikh 实验，应 TechCrunch 要求复测）
- **核心内容**：在让模型"二选一"支持某场选举竞选中候选人的测试中，xAI 的 API 会附加约 1,240 个研究者没有写过、也无法查看或删除的额外输入 token，研究者称其为潜在的"隐藏指令"，并认为其不太可能来自模型权重。关闭联网搜索复测 30 场：GPT（OpenAI）在给出候选人姓名时 24/30 选择民主党人、1 次共和党、5 次拒绝；Grok 的共和党倾向消失——27/30 拒绝选择，3 次均选民主党。研究者的结论："GPT 的倾向已经写在权重里；Grok 的倾向则真的来自搜索模式——检索词与信息来源决定了结果。"时点敏感：距 11 月 3 日美国中期选举不到两周。
- **背景/影响**：两项发现各有分量——"API 隐形注入"直指模型供应链透明度（系统提示/检索增强注入的边界），"搜索模式决定倾向"则把"AI 偏见"从模型内部问题扩展到检索生态问题；对 Agent 产品的可审计性（输入不可见 token）与搜索类 Agent 的信源治理是直接警示。

## 8. 研究称九个前沿模型生成的文本系统性更"难读"：句法特征偏离人类写作优化方向

- **发布时间**：arXiv 提交 2026-10-21（2610.29162）；Hacker News 10-24 讨论，146 分/143 评
- **来源**：arXiv（T. H. Clark、M. B. Martin、K. Mahowald）、Hacker News
- **核心内容**：论文构建跨领域 AI 生成文本语料，测量与人脑处理难度相关的心理语言学特征（对象关系从句、长句法依赖、低频 n-gram 等）。结果：与人类写作相比，全部九个前沿及准前沿模型都更频繁使用"无生命主语 + 有生命动词"搭配与低频 n-gram，多数模型还使用更长依赖、更多名词堆叠与压缩的对象关系从句；不同模型家族差异显著。作者提出并检验一个解释假说：人类语言为成功沟通而优化，而模型的训练目标并非如此。
- **背景/影响**：把"AI 味"从直觉变成可测量的句法指标族，为 AI 文本检测、可读性调控与模型对齐（面向人类处理效率优化）提供了特征级工具；对内容生产管线中"AI 文本人性化"环节是直接可用的诊断维度。
- **原始链接**：
  - https://arxiv.org/abs/2610.29162
  - https://news.ycombinator.com/item?id=50223647

## 10. gpu-unlock：把 RTX 30 系 FP/BF16 吞吐解锁到专业卡水平的内核模块开源

- **发布时间**：项目仓库 2026-10-18 创建、10-24 持续更新；Hacker News 10-24 提交，170 分/61 评
- **来源**：GitHub（Zagitta/gpu-unlock）、Hacker News
- **核心内容**：一个 Linux 内核模块，结合"CMP 解锁器"的 V67/PLM 技术与 UEFI 方案的驱动前时序配置，在 NVIDIA 驱动加载前写入速度选择器（SS0=0x88888888，选满速 BF16）并执行 FLR，从而把 GA102/GA103/GA104/GA106 消费卡（RTX 3090 Ti 等）的 FP/BF16 FMA 指令发射速率翻倍至专业卡 equivalents。作者称其优势是无需随驱动版本更新反复打补丁（不修改 NVIDIA 驱动本身）。
- **背景/影响**：延续消费卡解锁专业算力的探索路线（此前多为改变 RPM/功率限制），若稳定可复现，将直接改善二手 RTX 30 卡做本地推理的性价比；属社区硬件改造项目，稳定性、保修与合规风险需自行评估。
- **原始链接**：
  - https://github.com/Zagitta/gpu-unlock
  - https://news.ycombinator.com/item?id=50219700
