## 6. "SMS of Death"：一条零点击短信可远程崩溃 Android 电话进程并掉线紧急呼叫

- **发布时间**：2026-10-29（公开技术披露；漏洞 2026-05-05 经 Android VRP 报告，10 月安全更新已修复）
- **来源**：研究者站点（一手 PoC 与披露）、Hacker News（314 分/174 评）
- **核心内容**：Android 电话框架 WapPushOverSms.decodeWapPdu() 将 WSP 头部长度按 uintvar 读出后未做范围检查即强转为 int 并用作数组大小：一条特定构造的 WAP Push 短信（端口 2948）5 字节头 88 80 80 80 00 解码为 0x80000000、强转后成负数，触发未捕获的 NegativeArraySizeException 使 com.android.phone 崩溃。表现为零点击、无感的远程拒绝服务：通话被掉线（含紧急呼叫），普通用户无法自行恢复（仅 ADB 可修复），持续发送可使其反复崩溃。研究者 2026 年 5 月 5 日经 Google Android & Devices 漏洞奖励计划报告，修复随 2026 年 10 月 Android 安全更新发布，10 月 29 日公开细节与 PoC。
- **背景/影响**：典型"无害内存安全类 bug、极高可用性影响"的案例：IoT/车载等长期不打通话补丁的 Android 设备将长期暴露，攻击成本几乎为零。对运维侧的提醒是 10 月 Android 补丁应视为高优先级，尤其对依赖语音紧急呼叫的场景。
- **原始链接**：
  - https://smsofdeath.com
  - https://news.ycombinator.com/item?id=50285452

## 9. Claude Code 后台 Agent 摘要机制被测算占 16-23% API 开销：每 30 秒发送完整转录生成 3-5 词状态行

- **发布时间**：2026-10-29（HN 提交 03:33 UTC；配套 GitHub issue 已开）
- **来源**：第三方测量（gist）、anthropics/claude-code 官方仓库 issue #86879、Hacker News（558 分/224 评）
- **核心内容**：团队 Flamerix AI 公布对 Claude Code 的遥测测量（OTEL 原始载荷，按 query_source 归组）：每个工作中的后台 Agent 约每 30 秒向其自身模型（通常为 Opus）发送一次完整会话转录，要求"用 3-5 个词描述最近的动作"，结果仅用于 Agent 面板的状态标签；一周实测 agent_summary 请求占总 API 请求 19.7%、估算花费的 16.4%（超过主对话的 15.7%），其中 96% 花在 Opus 上；另一份 4 小时重子智能体会话（27 个子 Agent、1496 个请求）测得占请求 22.7%、加权 token 约 18%。官方仓库已有关停该行为的功能请求 issue，作者发布了将其降为零的 Bun preload 补丁。注意：原 gist 发布后标题与内容曾被作者改写，但核心机制与量级已获官方仓库 issue 及多方独立测量交叉印证。
- **背景/影响**：这是 Agent 工程成本审计的教科书案例：一个"看不见的 UI 功能"（状态行）以全量转录为代价，可吞掉五分之一的推理预算——Agent 平台的每次隐式模型调用都应可观测、可归因、可关停。对自建多 Agent 系统的启示：状态摘要类调用应使用小模型+增量摘要+缓存，并把 query_source 级成本核算纳入默认遥测。
