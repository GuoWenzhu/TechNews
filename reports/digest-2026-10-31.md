## 1. 官方 Claude Code 扩展遭篡改植入 SSH 后门：Cursor 市场带毒 11 小时，至多 5,000 名开发者受影响

- **发布时间**：2026-10-29（Cursor 官方安全公告 12:00 UTC；恶意版本上线窗口 10-29 09:27–20:35 UTC）
- **来源**：Cursor（一手安全公告）、Phorion（一手技术分析）、Kevin Beaumont/DoublePulsar、The Verge、The Register；Hacker News（736 分/460 评、652 分、398 分三贴）
- **核心内容**：Cursor VS Code 扩展市场出现非 Anthropic 构建的篡改版官方扩展 Anthropic.claude-code 2.1.312/2.1.313（Windows/macOS），在线约 11 小时，至多 5,000 用户受影响。攻击者在 extension.js 头部注入 66 行加载器，Node 加载模块时即执行（无需任何交互）：向 ~/.ssh/authorized_keys 写入攻击者 Ed25519 公钥（注释 svc-telemetry）、按系统落持久化（macOS com.apple.sysmond.plist、Windows 计划任务、Linux @reboot cron）、采集主机名/用户名/系统/主目录/公网 IP/Git 邮箱并回连 134.209.82.225 建立反向 SSH 隧道；卸载扩展不足以清除独立驻留脚本。macOS 上因载荷一处权限判断 bug（非 root 查询"远程登录"状态返回错误但退出码为 0），未主动开启 SSH 的机器入站通道未打通，影响减轻但仍落键与驻留。处置：Cursor 下架涉事版本并临时关闭市场核验（确认无其他扩展被篡改），同时从 npm 与 VS Code 注册表拉除 2.1.313；Anthropic 员工 Felix Rieseberg 表示"非 Anthropic 系统或员工设备失陷，系恶意行为者利用 Cursor 市场访问权发布篡改副本"，官方渠道版本不受影响；攻击者获得市场发布权限的具体手法尚未披露。
- **背景/影响**：AI 编程工具分发链的首个大规模供应链失陷事件：IDE 扩展以 IDE 与用户完整权限运行、加载即执行，直接触达源代码、凭据与开发工具链，"官方扩展 + 官方市场"的信任假设被击穿。行动项：排查是否安装过涉事版本、检查 authorized_keys 中的 svc-telemetry 公钥与 IoC IP、轮换开发机凭据；对平台方，市场发布通道的权限审计与包签名校验应视为刚需。

- **发布时间**：2026-10-30（OpenAI 官方博客，RSS 09:30 UTC）
- **来源**：OpenAI（一手）
- **核心内容**：OpenAI 发文《Making it easier for websites to express AI training preferences》，宣布将支持 robots.txt 中的一种通用信号（common signal）：网站运营者可在一个文件里一次性向所有参与该约定的 AI 提供商声明"内容是否可用于生成式 AI 基础模型训练"的偏好，无需再逐家配置各公司爬虫的 User-Agent 规则。

## 7. Tangled：构建在 AT Protocol 上的首个联邦化代码托管平台

- **发布时间**：2026-10-30（Tangled 官方博客）
- **来源**：Tangled（一手）；Hacker News（217 分/69 评）
- **核心内容**：Tangled 系统阐述其"联邦化代码托管"路线：构建在 AT Protocol（Bluesky 的底层开放协议）之上，自称首个真正联邦化的代码托管平台——可以只自托管部分组件（如 Git 存储或 CI runner），也可托管全部（API 服务器与 UI），且无论哪种选择都能与其他实例无缝协作；借助 AT Protocol 的 firehose 订阅与扩展机制，开发者可编写自定义"knot"服务（官方示例：一个跑在 Cloudflare Workers 上、用其 Artifacts 产品做 git 存储的协作组件）。
- **背景/影响**：把"电子邮件式"的开放协议路线带回代码托管：在 GitHub 单点依赖与集中式 forge 供应链风险（昨日 Alpine Linux GitLab 攻击未遂即为最新案例）反复引发担忧的背景下，"自托管 + 联邦协作"提供了第三条路——既不像全托管那样集中，也不像纯邮件补丁流那样牺牲体验。对自建研发基础设施的团队，AT Protocol 的身份与数据层是值得评估的新基座。

## 10. Cloudflare 公布 eMudhra 弱密钥利用追踪：8 把私钥可直接从公开证书恢复，大网络过半探测仍接受失陷链

- **发布时间**：2026-10-30（Cloudflare 博客 17:38 UTC）
- **来源**：Cloudflare（一手遥测与修复时间线）
- **核心内容**：Cloudflare 公布 eMudhra 弱密钥事件的利用与修复追踪：8 把失陷中间 CA 私钥弱到"可直接从公开证书恢复"——其 RSA 私钥指数就是 4、56、66、115、155、156、230、237 这几个小数字；Cloudflare 于 10-19 得悉后数小时内完成自身关键服务的证书换发。互联网范围遥测显示修复远未完成：约 30-40% 的旧浏览器仍接受失陷链，大型网络中过半探测仍接受失陷链，且已有利用尝试的观测证据。
- **背景/影响**：与昨日报道的"Apple 命令行工具仍信任失陷 eMudhra 证书"同源，是 CA 行业罕见的灾难性失败：不是密钥被窃，而是密钥生成流程产出了人人可算的私钥。行动项：信任库清理不能只等操作系统与浏览器推送——mTLS、私有 PKI、老客户端与嵌入式设备的信任链需要主动核查；中间 CA 事件的长尾将以月计。
