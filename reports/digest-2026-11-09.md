## 2. llama-modchip v2.4：284B MoE 模型纯 CPU 跑进 64GB 内存，零 GPU

- **发布时间**：v2.4.0 发布 2026-11-04 00:24 UTC（项目仓库 10-29 创建、11-08 仍在推送更新）；HN 讨论 2026-11-08 10:22 UTC，343 分
- **来源**：GitHub synchopate/llama-modchip（一手，附技术论文 PDF、补丁、基准与评测脚本）；Hacker News
- **核心内容**：目标：把 DeepSeek-V4-Flash（总参 284.33B、激活 13.17B，43 层 MLA + 256 路由专家）塞进普通桌面内存纯 CPU 推理。量化：官方 UD-IQ1_S 版本占 76.87 GiB 超出 64GB 机器约 62.5 GiB 可用内存；项目自研 Fractal-64 分块格式（GGML_TYPE_Q2_0，64 权重块 + BF16 缩放）与混合分配——嵌入层、稠密层、43 个共享专家与 MLA 关键投影保留 Q4_K/Q5_K/F32，路由专家主体 IQ1_S（附解析式 SwiGLU-H2 二阶尺度匹配）、敏感边界层升到 IQ2_XXS/IQ1_M——总占用降到 56.56 GiB（约 1.71 bpw），全模型 + 256K 上下文 KV 峰值 VmRSS 57.61 GiB 零交换驻留。内核：AVX-512BW 四级（ZMM 寄存器/L1D/L2/L3）多列分块替代单列量化矩阵向量循环，Zen 5 16 核 prefill 从 25.0 提到 44.36 tok/s（+77%）、decode +53%（9.1–14.7 tok/s）；寄存器驻留 MQA8 FlashAttention 与非临时访存让冷专家权重不冲刷热 KV。智能体侧：1.64 MB Zobrist n-gram 起草器（借鉴 Stockfish PVS）做自推测解码，/dev/shm KV 快照 13.1 ms 恢复一个 40 工具 Claude Code 会话上下文。外围：Nemotron-3.5-30B-A3B 在 16–32 GB 机器达 25–60.4 tok/s，Threadripper 8 通道 DDR5 上 30B 达 111.6 tok/s；默认 Top-6 全专家评估，repo 自报与未修补运行时 logit 余弦相似度 1.00000；附 CPU 性能排行榜、论文 PDF 与 Apple Silicon/Windows/Fedora 部署脚本。
- **背景/影响**：把"旗舰 MoE 必须 GPU 集群"的门槛再压低一档——1.71 bpw 的质量代价是最大疑问（评测为本项目自报，需独立复现），但其中 CPU 分块调度（MoE 冷权重绕行 L3、保热 KV）、KV 快照秒级恢复智能体上下文、n-gram 自推测三件事对端侧/本地大模型部署都有直接参考价值；与近期 MaxxBench、Vercel Gateway 上的 DeepSeek V4.x 生态热度呼应，开源 CPU 推理社区（llama.cpp 补丁系）仍在快速前移。

## 3. Outlook.com 自 11-05 起静默拒收无 DMARC 域名的部分邮件：无公告、波及小发送方

- **发布时间**：事件自 2026-11-05 起被观测；MailRoute 博客 2026-11-06 发布；HN 讨论 2026-11-08 19:20 UTC，201 分
- **来源**：MailRoute（邮件网关服务商，出自站运维日志的一线记录）；Microsoft Tech Community（2025-05 高发送量新规，官方对照）
- **核心内容**：2026-11-05 起，outlook.com / hotmail.com / live.com / msn.com 开始拒收无 DMARC 记录域名的"部分"邮件，退信为 `550 5.7.1 Message rejected: Message lacks SPF/DKIM/DMARC Auth Records (AS9031519)`。与微软 2025-05 公布的"日发 5000+ 域名必须过 SPF/DKIM/DMARC"规则有三点关键差异：其一，本次波及普通小量发送者——一条小办公室发出的回复也会被弹回，而非只针对批量营销；其二，截至 11-06 微软未发布任何 postmaster 公告、博客或服务健康条目；其三，错误码不说明具体哪项失败——被弹域名大多 SPF 正常、不少还有 DKIM，缺的是把两者与 From 域名绑定的 DMARC 记录。最危险的是它"只拒一部分"：同一域名的邮件一封过、一封弹，重发可能成功——发件人以为只是抖动，收件人永远不知道有邮件来过。修复只需一条 DNS TXT 记录：主机名 `_dmarc`、值 `v=DMARC1; p=none`（前提：SPF 或 DKIM 须对 From 域对齐，否则 DMARC 仍不过）。
- **背景/影响**：各大邮箱商的既定路径——要求从批量发送者起步，随后静默扩为全员基线（Gmail/Yahoo 2024 年已先行）。对依赖触达个人邮箱的通知/验证码/发票类系统，`p=none` 已是投递底线而非最佳实践；未配置域名应立即自查（`dig +short TXT _dmarc.你的域名`）并补齐对齐的 SPF/DKIM。

## 4. "智能体记忆需要它的 OpenTelemetry 时刻"：跨工具共享记忆格式的公开提案

- **发布时间**：2026-11-07（LoreKit 博客）；HN 讨论 2026-11-08 08:40 UTC，164 分
- **来源**：lorekit.io（作者为开源记忆工具 LoreKit 开发者、Dash0 工程师，文中主动披露利益关系并声明"若共享规范形状与 LoreKit 不同，LoreKit 应当采纳规范"）；Hacker News
- **核心内容**：现状：一套典型 2026 开发环境并存 4 种以上互不兼容的智能体记忆——AGENTS.md/CLAUDE.md/Cursor 规则文件（人工编辑、永不遗忘）、Anthropic memory tool 的 /memories 文件（模型自管理）、GitHub Copilot Memory（仓库级事实+28 天未用即删，带代码引用）、以及 Letta 核心记忆块、Mem0 抽取事实、LangGraph BaseStore、MCP 参考记忆服务器（知识图谱）、Graphiti/Zep 时序图谱等；社区里"我又造了一个记忆层"的帖子层出不穷，恰说明问题真实——缺的不是工具而是协议。既有提案（MacPaw Portable Memory `.mem` 束、Open Memory Protocol ZIP、Cognee COGX）都只解决"导出"（跨厂商搬家）；作者指出第二个正交问题无人覆盖——"live addressing"：CI 机器人、编辑器智能体、评审机器人并发读写同一地址如何达成一致。提案：对照 2019 年 OpenTracing+OpenCensus 合并成 OpenTelemetry 的经验，主张在四层达成共享——数据模型（address/key/kind/lifecycle/written_by 信封 + 正文，示例记录用 frontmatter+Markdown 给出）、语义约定（global/project/repo/branch 地址层级、`vcs.*`/`ci.*`/`agent.*` 属性命名空间的版本化注册表）、MCP 操作契约（write/read/list/search/archive）、一致性测试（往返无损、未知属性存活、过期行为）；存储、排序、嵌入与界面留给竞争。正面回应 xkcd 927：标准成立靠既有项目合并而非新增第 15 个格式；并把共享记忆的提示注入风险作为规范必须记录 written_by、支持签名与"记录指向所依赖代码"的理由。
- **背景/影响**：继上周 Anthropic "Components of Agent Memory" 研究之后，智能体记忆连续第二周成为工程焦点；MCP 与 AGENTS.md 均已归属 Linux 基金会 Agentic AI Foundation，中立托管位现成。对做多智能体/跨工具记忆的团队，这是一份少见的"全谱系对比 + 分层规范框架"输入；"导出 vs 并发寻址"的二分尤其值得借用到自研记忆层设计。

- **来源**：Science（AAAS 期刊调查报道，一手）；Inside BCI（行业转述核验）
- **核心内容**：Science 调查发现，Emotiv、Interaxon（Muse 头带）等消费神经科技公司已积累数千万小时量级的脑电（EEG）记录，并用其训练业内所称的 "brain foundation model"——如 Interaxon 正构建的模型，用于加深对睡眠与专注期大脑活动的理解并孵化新产品；报道以一位 Muse 用户为例：他不知道自己的头带数据在喂 AI 模型。政策面：在设有隐私政策的厂商中，除一家外都允许与第三方共享"匿名化"数据；受查厂商中仅 6 家明确承诺不出售用户脑数据，多数政策对"脑数据是否用于 AI 训练"只字未提。监管面：美国科罗拉多（2024-04）、加州（2024-09）刚把神经数据纳入生物特征/个人敏感数据保护，欧盟 GDPR 对"神经数据是否属特殊类别"尚无统一解释——消费神经技术采集与 AI 训练用途基本处于告知真空。
- **背景/影响**：神经数据是继位置、人脸之后第三个被规模化采集的生理信号，而消费头带以"专注/冥想/睡眠"的低敏感包装成为最顺滑的采集入口。对隐私合规与端侧生理数据产品的直接含义：采集告知、训练用途披露与退出机制将进入监管清单与企业采购要求；做 BCI/健康可穿戴的团队应把"训练用途单独同意"预埋进数据管线。
