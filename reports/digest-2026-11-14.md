## 1. OpenAI 发布 ChatGPT Wallet：智能体"持卡代付"不用真实卡号，每笔购买强制安全核验

- **发布时间**：2026-11-13（OpenAI 官方博客 15:00 UTC；TechCrunch 16:00 UTC、The Information 20:20 UTC 同日跟进）
- **来源**：OpenAI 官方博客（一手）；TechCrunch、The Information（报道）
- **核心内容**：OpenAI 推出 ChatGPT Wallet，定位"为智能体支付设定安全新标准"：用户添加一次银行卡后，每笔购买前需审核商品、总价与所选卡片，并通过 Face ID/指纹等安全核验批准；批准后由支付网络下发支付令牌（payment token）替代真实卡号完成扣款，商家与智能体始终接触不到用户实际卡号，同时保留原卡的积分奖励与争议保护。合作方为 American Express、Mastercard 和 Visa。首发范围：通过 OpenAI 购物智能体 dots 使用，限美国 18 岁以上 ChatGPT Pro 订阅用户、美国发行的合规卡。同步发布 Commerce Partner Playbook（developers.openai.com/commerce），指导商家三件事：认领并上传商品数据、用 Web Bot Auth 配置 CDN/防火墙避免误拦智能体签名请求、与风控与收单方打通让合法智能体购买不被误拒——OpenAI 已与 Forter、Riskified、Sardine、Signifyd 等风控商及 Adyen、Checkout.com、Stripe 等支付服务商合作适配。官方称 ChatGPT 周活 12 亿人，购物是其中高频行为。路线图：未来允许用户设定消费限额、品类与时段等参数，配合生物核验与授权记录实现"预授权、全托管"的智能体代购。
- **背景/影响**：继本周 Anthropic/Coinbase 系的 x402 加密支付路线后，OpenAI 选择了"卡组织令牌化"路线把智能体支付接入现有清算体系——两条路线的竞争本质是：智能体经济的资金通道走传统金融基础设施还是加密原生存 rails。对商家而言，"是否会被智能体访问、风控是否误拒"成为新的流量与转化问题；Web Bot Auth（签名请求身份）与令牌化支付的组合，是智能体身份与支付两大基础设施的首次成套产品化。

## 2. Sierra 的 Personal Agent Protocol（Poppy）发布 1.0：Shopify 全量商家自动支持，Meta Muse 默认优先发现 Poppy

- **发布时间**：2026-11-13（Sierra 官方博客 17:00 UTC）
- **来源**：Sierra 官方博客（一手）；personalagentprotocol.org 官方规范站；TechCrunch 无独立稿，合作方公告（Shopify/Mercury 等）为准
- **核心内容**：Sierra 上月联合 Meta、Genesys、Instinct、NiCE、Rocket、Shopify、Stripe、Walmart 等初始设计伙伴公布的 Personal Agent Protocol（Poppy）发布 v1.0 规范（personalagentprotocol.org/docs/1.0/spec）。Poppy 定义"个人智能体如何以声明方式接入企业"：智能体到访一个站点时先发现 Poppy 文件，获知自己被允许做什么、如何认证（OAuth）、如何被用户控制，主要复用 MCP、OpenAPI、UCP 等既有标准。三项落地进展：(1) Shopify 为平台全部商家自动启用 Poppy——每个店铺默认发布 UCP（Universal Commerce Protocol）+ Poppy 文件，UCP 管购物执行（找商品、加购、结账），Poppy 管"智能体亮明身份、获知权限"，由 Shopify 共同署名的 commerce extension 连接两者，并要求智能体在关键动作前征得用户同意；(2) Meta 的消费级智能体 Muse 现在访问任何站点都自动优先查找 Poppy；(3) 设计伙伴从上月的约 40 家新增 60 家、总数破百（Affirm、Delta、Intuit、Salesforce、Twilio、Wayfair、Zoom 等），Mercury（银行查询/转账需过账户审批策略）、Synchrony、土耳其航空已上线真实场景。官方提供实施套件与校验器，企业可自行部署。
- **背景/影响**：智能体-企业接入层正在从"各家私有 API + 爬虫灰区"走向开放协议标准化：Poppy 管"身份与权限发现"、UCP/MCP 管执行，与昨日 ChatGPT Wallet 的支付令牌、Web Bot Auth 的请求签名拼成完整的"智能体商业栈"。对做企业侧 AI 落地的团队，"发布一个 Poppy 文件让外部智能体可编程地接入"可能很快成为像 SEO/开放 API 一样的标配。

## 4. Apache HTTP Server 修复 HTTP/2 关键 RCE（CVE-2026-119618）：Anthropic OSS Scanner 与 Google Cloud 联合发现，2.4.71 发布

- **发布时间**：2026-11-11（Apache 2.4.71 发布，官方安全公告收录；Wiz 分析 11-12，HN 讨论 11-12T02:11Z 起 367 分）
- **来源**：Apache 官方安全公告（一手）；Wiz Research 技术分析；Hacker News 讨论
- **核心内容**：Apache HTTP Server 发布 2.4.71，修复三个 CVE，其中关键级 CVE-2026-119618 位于 HTTP/2 模块 mod_http2 的 `assign_headers()` 函数：并发线程共享资源时同步不当触发竞态，远程未认证攻击者可造成堆内存破坏并实现任意代码执行（RCE）。影响范围：Apache HTTP Server 2.4.55–2.4.70（启用 HTTP/2 时），GitHub 独立 mod_h2 模块 2.0.8–2.0.42；修复版本为 2.4.71 与 mod_h2 2.0.42+（修复提交 824beab）。发现方为 Anthropic 的 OSS Scanner（内部编号 ANT-2026-MAPKT6MZ，2026-10-26 报告）与 Google Cloud 漏洞研究团队的 Anthony Weems、Simon Scannell（2026-11-03 报告），属独立重复发现。Wiz 同步披露：其云环境数据中 64% 的环境存在受影响资源、51% 存在公网暴露实例；官方确认目前无公开利用（exploit）与在野利用报告。临时缓解：无法立即升级时可关闭 HTTP/2（h2/h2c）仅留 HTTP/1.1。
- **背景/影响**：这是"AI 安全扫描器发现真实高危 CVE"的一个标志性案例——Anthropic 的自动化 OSS 扫描与 Google Cloud VR 人类团队在同一个月各自命中同一竞态缺陷，AI 辅助漏洞发现的能力已经进入实战交付区间。运维侧建议把 2.4.71 升级列入紧急补丁窗口：mod_http2 面向公网、触发面广，且无需认证。

## 6. Cloudflare 开源 Kitesurf：跑在 Workers 上的无状态 AI 智能体浏览器引擎（Apache 2.0）

- **发布时间**：2026-11-13（Cloudflare 官方博客 20:20 UTC）
- **来源**：Cloudflare 官方博客与 GitHub 仓库（一手）
- **核心内容**：Cloudflare 将 Kitesurf——8 月发布、9 月加入 WebMCP 支持的无状态浏览器引擎——按 Apache 2.0 开源（github.com/cloudflare/kitesurf）。定位：给 AI 智能体的轻量浏览器，完全跑在 Cloudflare Workers 上，无需浏览器容器即可解析 HTML、应用 CSS、执行页面 JavaScript 并渲染截图；支持 Chrome DevTools 协议（CDP），Puppeteer 与智能体 harness 可直接连接。技术构成：Blitz（HTML/DOM/布局/绘制）、Stylo（CSS，来自 Servo）、Boa（WASM 内 JavaScript 兜底执行）等 Rust 生态包编译到 WebAssembly；架构分 Engine（会话与连接管理）、PageScript（页面与 JS 执行）、PageRenderer（渲染）三部分，另附 Kitesurf CLI。开发者可本地运行（wrangler，127.0.0.1:8787）、用 `pnpm run deploy` 部署到自己的 Workers 账户（需付费计划，页面隔离依赖 Dynamic Workers），替代 Browser Run 托管 API。
- **背景/影响**：智能体的"浏览器执行环境"正在成为独立的基础设施品类：相比给 agent 起一个 Chromium 容器，无状态 + 边缘分布 + CDP 兼容的方案在成本与扩展性上低一档；开源后自托管实例可行，对做智能体沙箱、网页自动化与边缘侧 agent 部署的团队是可直接复用的引擎底座。

## 7. Edge0 开源 145B 端侧模型：笔记本本地推理峰值内存 29GB、解码 80+ tokens/s，主打编码与智能体任务

- **发布时间**：2026-11-12/13（Edge0 官方博客发布权重与推理框架；HN 讨论 11-12T23:06Z 起 338 分）
- **来源**：Edge0 官方博客、Hugging Face 权重页与 GitHub 仓库（一手）；Hacker News 讨论
- **核心内容**：Edge0 开源 Edge0-145B 与 Edge0-120B 权重（Hugging Face，NVFP4 格式）及统一推理框架、一键部署工具（GitHub），自称“首个可在个人电脑本地运行的开源 145B 模型”：兼容笔记本（MacBook Pro 等）本地推理，报告峰值内存 29GB、prefill 1,100+ tokens/s、解码 80+ tokens/s、典型功耗约 120W，支持 128K–256K 上下文且长输入速度基本不变。技术路径四层协同：(1) 架构上稀疏专家共享大矩阵——每 64 个专家共享两个大矩阵、各自仅保留小差量参数，145B 总参数中每步仅约 10B 参与计算；(2) 训练即按端侧部署约束设计，而非云模型后压缩；(3) 加载上 GPU 显存（热专家）→ 系统内存（约 40GB 专家库）→ SSD（约 48GB 词表按需读）三级流水并行，读取与计算重叠；(4) 调度上 CPU/GPU 并行加推测解码。基准为官方内部评测：Terminal-Bench 2.1 86.52、DeepSWE 1.1 64.6、GPQA-Diamond 90.4、IFBench 80.6、AA-LCR 79.3，六基准均值 72.8（对比 Qwen3.8-Flash-Next 均值 71.7、估算 4-bit 部署内存约 70GB——即约 40% 内存达到相当能力）；官方同步演示本地完成视频生成、Blender 曼哈顿级 3D 场景、可玩游戏、真实无人机避障寻物、KiCad PCB 设计等智能体工作流，全程无云端调用。首发支持 macOS/Windows/Linux（Apple M 系列、RTX 4090/5090/Spark），公司自述 9 月发布的手机端 Edge0-35B 曾登顶 Hugging Face Trending、开源模型三个月下载超 1,500 万次。
- **背景/影响**：若 29GB/80 tokens/s 数据经社区复现，“145B 级本地智能体模型”将把 vibe coding 与复杂智能体工作流从云侧拉回端侧，端云分工从“云端优先”走向“端侧优先”的信号事件；需注意全部对比基准为厂商内部评测，应以第三方复测为准。对本地部署/微调实践者，专家矩阵共享与三级存储流水线是可直接借鉴的推理工程路径。

## 10. 权重取证报告：四家中国实验室的六个前沿新模型检出受出口管制 Blackwell GPU 指纹

- **发布时间**：2026-11-12（报告 11-12 修订版；TechCrunch 11-13T18:40 UTC 报道；HN 11-12T21:56Z 起 355 分）
- **来源**：unemploymentlabs《Checkpoint Forensics》报告（独立研究，方法公开可复核）；TechCrunch（报道）
- **核心内容**：一份针对公开模型权重的取证分析报告称，DeepSeek、月之暗面（Moonshot AI）、MiniMax、蚂蚁集团自 2026 年 4 月以来发布的六个模型在数值模式上匹配 Nvidia 受出口管制的 Blackwell GPU：DeepSeek-V4-Flash（B200/B300）、DeepSeek-V4-Pro（GB200/GB300）、Kimi K3 与 K3.1-Pro（GB200/GB300）、MiniMax-M3（B200/B300）、Ling-3.1-flash（GB200/GB300）；四家此前的模型均为 Hopper 一代指纹（实验室此前披露为 H800）。方法：完全依据模型自身公开权重——恢复初始化痕迹后，在约 6 万亿种"种子 × 硬件布局"组合中搜索能复现者；对 DeepSeek-V4-Flash 与 Kimi K3 另在物理 Blackwell 芯片上复核确认；证据强度 49–1385 sigma，24 个已知答案模型全部命中，最弱单项亦达 20 sigma。规模估算：五个训练合计约 1.2 万张 Blackwell，最大单次（Kimi K3）约 4,500 张、折合约 1.15 万张 H100。报告同时指出：阿里 Qwen、智谱 GLM、腾讯、小米、StepFun 最新模型仍读出 Hopper 指纹，美团 LongCat-2.0 称全用自研 ASIC 超算未见 Nvidia 指纹。作者强调：证据只说明"用了该硬件"，不证明芯片所在地、获取途径或是否违反出口管制；特制 AMD 硬件是唯一备选解释，已对 DeepSeek-V4-Flash 排除、对其余五模型认为极不可能。
- **背景/影响**：这是出口管制争论中首个"从权重反推训练硬件"的系统性技术证据，把政策辩论从匿名信源推向可复核的取证方法；无论后续各方如何回应，"模型权重可泄露训练基础设施指纹"本身对模型发布方就是新的安全与合规变量。
