## 1. 阿里巴巴发布 Qwen4-Max：2.4 万亿参数稀疏 MoE、1M 上下文、仅提供 API 不再开源权重

- **发布时间**：2026-11-16（官方博客与阿里云通稿；此前 11-11 曾开启预览）；Hacker News 讨论 11-16 02:14 UTC 起 850+ 分
- **来源**：Qwen 官方博客、阿里云通稿（一手）；The New Stack、heise、Bloomberg（经 TNW 转述）、MarkTechPost（报道）
- **核心内容**：Qwen 团队发布 Qwen4 系列首个旗舰模型 Qwen4-Max，定位"工作、创作与发现的 AI 队友"。官方口径：总参数 2.4 万亿的稀疏 MoE 架构，每 token 激活约 71B 参数，另有 328B N-gram 嵌入参数；支持文本/图像/视频原生多模态输入，上下文窗口 1M token、最大输出 393K token；主打编码、复杂智能体任务与视觉推理。官方称编码基准成绩超过 GPT-6.1-Sol 与 Claude Opus 5.5、在 Code Arena 真实编码榜单列第 6（均为官方自评口径，尚无独立核验），并通过 API 降价使单位任务平均成本下降 62%。与上一代 Qwen3.8-Max 曾开放权重不同，Qwen4-Max 仅通过阿里云/QwenCloud API 提供（输入 $1.5/百万 token、输出 $4.5/百万 token），官方表示更小的 Qwen4 型号后续会开源但未给出时间表。
- **背景/影响**：Qwen 系列长期是开源权重生态的主力，旗舰转向纯 API 闭源是其在 IPO 进程中商业化与差异化竞争（对标 GPT/Claude 旗舰）的明确信号；1M 上下文与多模态输入继续压低长文档与视频场景的门槛，中小型开源型号的去向将决定其对开源社区影响力的延续性。

## 3. 美国商务部发布出口管制临时规则：管制"远程访问境外算力"，并撤销 AI 扩散规则

- **发布时间**：2026-11-16（商务部工业与安全局 BIS 发布临时最终规则 IFR；TechCrunch 15:02 UTC、The Information 18:13 UTC 报道）
- **来源**：BIS 规则文本（一手）；TechCrunch、The Information（报道）
- **核心内容**：根据临时最终规则，出口、再出口或转让 AI 芯片与服务器至全球任何数据中心时，若该数据中心可能向中国等受限国家（D:5 组，含俄罗斯、伊朗、朝鲜等约 23 国）的企业提供算力，须申请许可。规则要点：适用于总算力超过 1200 万 TPP 的数据中心（约合 750 张 Nvidia H100/H200 的峰值算力），覆盖通过中间商/代理的间接访问，并要求数据中心运营商持续核查客户的股权结构与实际活动；对马来西亚、新加坡、印度尼西亚、泰国、巴西新增许可要求（官方称这些国家"转用风险高于常态"，美国公司自用芯片豁免）；现存数据中心运营商须在规则生效后 90 天内取得许可；商用推荐系统（电商/社媒）不适用。规则同时正式撤销拜登政府 2025 年 1 月的 AI 扩散规则（AI Diffusion Rule）。规则文本称这是"现有管制的逻辑延伸"，目的是阻止受限国家企业利用美国"超级智能（SI）"半导体训练先进模型。
- **背景/影响**：把"物理出口"管制扩展为"远程访问"管制，直接封堵中国 AI 企业此前租用东南亚/中东等地算力的绕行路径（The Information 同日报道 MiniMax、Z.ai 等中国 AI 股价因此进一步大跌）；叠加 Nvidia CEO 危机与本周财报，政策不确定性将影响全球算力布局、云厂海外数据中心客户合规成本与芯片需求预期。

## 7. uBlock Origin 被发现通用 XSS：恶意网站可借元素选择器注入任意"可信过滤器"（已修复）

- **发布时间**：研究者披露 2026-11-15（iter.ca）；Hacker News 11-16 02:04 UTC 起 597 分
- **来源**：研究者博客 iter.ca（一手分析）；uBlock GitHub 安全通告 GHSA-cmqw-9r2w-6wv2（一手）；Hacker News（讨论）
- **核心内容**：安全研究者披露 Firefox 版 uBlock Origin（MV2）的一键式通用 XSS 漏洞：恶意网站可定位元素选择器（element picker）的扩展内部 URL（借默认广告过滤规则对 fetch 的钩子泄露扩展 UUID），以不可见 iframe 嵌入选择器界面并用 postMessage 驱动它，再利用 opt 字段注入换行，让选择器替攻击者创建任意"可信过滤器"——这类过滤器可向任意网站注入 JavaScript 脚本（如 `#+js(trusted-rpnt, ...)`），从而在受害者后续访问的任何页面上下文中执行任意代码。作者说明该问题主要由 GPT-5.6 Sol 定位、人工验证，PoC 代码由 Claude 协助编写。官方已修复（选择器消息增加密钥校验等），MV3 版 uBO Lite 受影响程度较低。
- **背景/影响**：浏览器扩展的"可信能力"一旦被页面驱动，即成为跨站攻击面；对依赖 $js 可信脚本过滤的用户而言，及时更新 uBlock Origin 是硬要求。事件也再次示范"LLM 辅助漏洞挖掘 + 人工验证"的工作流已在真实安全研究中常态化。

## 8. FBI 通告：开源 AI 渗透工具 Artex 被用于真实入侵，"从接触到突破最短不足 3 小时"

- **发布时间**：FBI/IC3 闪发安全通告 2026-11-13；TechCrunch 2026-11-16 报道（首次广泛传播）
- **来源**：FBI IC3 通告（一手）；TechCrunch、Barracuda 官方披露、Microsoft 此前报告（佐证）
- **核心内容**：FBI 在闪发通告中确认，黑客自今年 7 月 Artex 公开发布以来，将其接入托管前沿大模型（Anthropic、OpenAI 系及开源/非美模型）用于自主化攻击，目标覆盖金融、政府、科技、国防、电信与律所等行业。已知案例：IT 管理巨头 ConnectWise 供应链入侵（微软 10 月归因疑似中国黑客，至少 2,250 家客户 M365 云环境被访问）；韩国多家金融机构被攻破、至少 6.8 万人个人信息被盗（多因缺少 MFA 等基础防护）；安全厂商 Barracuda 11-11 自曝因未撤销的第三方凭据遭 Artex 攻击并被迫全员轮换客户集成凭据。FBI 指出此类攻击"嘈杂"但速度极快，部分案例从锁定目标到实际突破不足 3 小时；工具开发者已将 Artex 转为闭源，但旧开源版本仍在广泛流传，且上周研究者发现有数百个 Artex 系统暴露在公网。
- **背景/影响**：官方首次系统确认"AI 自主渗透工具"从概念验证进入大规模实战；防守方依赖"发现-响应"的人力节奏将系统性落后，暴露面收敛、凭据生命周期管理与 MFA 等基础控制的价值被案例反复验证。攻击工具本身可被旁路访问（公开暴露的 Artex 实例）构成新的二级风险。

## 10. 独立研究者披露 OPTIMJACK：15 个知名网站加载的 Optimizely 标签被注入加密货币剪贴板劫持与银行卡窃取脚本

- **发布时间**：2026-11-16（研究者博客；Hacker News 21:08 UTC 起 185 分、219 评论）
- **来源**：独立安全研究者分析（一手，含 urlscan 证据与 IOC）；Hacker News（讨论）
- **核心内容**：研究者报告一个针对标签管理层（Optimizely CDN 上的实验脚本）的供应链注入活动 OPTIMJACK：受影响的 Optimizely bundle 末尾被追加加载 `1688360.cc/track.js`，载荷含四个模块——加密货币地址剪贴板劫持（支持 ETH/BTC/SOL/TRX/TON 等 8 条链，含 base58check/bech32 等真实校验以规避察觉，劫持 DOM 文本、输入值、剪贴板与 fetch/XHR 请求体）、银行卡信息窃取（钩取 POST 表单与 JSON，经 sendBeacon 外传）、页面 URL+Cookie+截图外传，以及仅对 iOS 设备注入的二阶段 `boot.js`。观察到 edition.cnn.com、zoom.com、bbc.com、salesforce.com、about.gitlab.com、hootsuite.com、stamps.com、virginmediao2.co.uk、hsbc 新加坡保险站等 15 个高流量站点的页面加载了该载荷（其中两家站点因 CSP `script-src` 策略拦截了执行）；除 Optimizely 外还见第一方 bundle、广告 wrapper 与 Jscrambler 保护脚本三条侧向载体。研究者给出排查方法：检索所加载 bundle 是否引用未知 `.cc`/`.icu` 域、监控 CSP 违规上报、用测试钱包地址验证粘贴-提交一致性，并公开 IOC 与文件哈希。
- **背景/影响**：再次证明"自己源码干净 ≠ 访客安全"——第三方标签层拥有页面级执行权限，营销/实验工具链成为支付与钱包场景的高价值投毒面；对金融、电商类站点，标签审计与 CSP 应纳入常规纵深防御。
