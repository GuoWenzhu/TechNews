## 1. NGINX 披露两个 HTTP/2 未认证 RCE 漏洞（CVE-2026-123633 / CVE-2026-123007），F5 同步发补丁

- **发布时间**：2026-11-18（F5 安全发布与协调披露同日；Hacker News 11-18 15:19 UTC 起 1,065 分）
- **来源**：Wiz Research 漏洞分析与披露时间线（一手）；F5 安全公告（一手）；Hacker News（讨论）
- **核心内容**：Wiz Research、Ikotas Labs、Metnir、Rapid7 与 Xint 五个团队独立发现了 NGINX 的两个 Critical 级 HTTP/2 远程代码执行漏洞，CVSS 4.0 评分均为 9.2。CVE-2026-123633 为 HTTP/2 use-after-free，Wiz 实现了带 ASLR 绕过的确认 RCE；CVE-2026-123007 影响范围可追溯到 2015 年的 NGINX 1.9.5。两个漏洞都存在于 NGINX 本体而非用户应用代码，利用前提是服务器启用 HTTP/2。披露时间线：10-21 Wiz 上报（F5 告知另一研究团队已先报同一漏洞）→ 11-10 F5 提供补丁评审 → 11-16/17 上报第二个漏洞并确认纳入计划中的 11-18 安全发布 → 11-18 F5 正式发布补丁并协调披露。NGINX 是全球使用最广的开源 Web 服务器，驱动超过 2.25 亿个网站。
- **背景/影响**：作为现代 Web 架构的默认"前门"，"未认证 RCE + 版本跨度长达 11 年"意味着大量生产环境需紧急升级；与本周 Java4Shell（OpenJDK）、上月 PHP2Shell 呼应，互联网基础软件的高危漏洞潮仍在持续，边界组件（NGINX/Java 运行时）的"默认配置即暴露面"值得各团队重新盘点。

## 7. 微软 ONNX Runtime 等 4 个仓库深夜从 GitHub 消失，与 agent-framework PyPI 投毒事件同期，官方尚无解释

- **发布时间**：2026-11-17 深夜起（Hacker News 11-17 23:18 UTC 提交、450 分；第三方跟踪站测得仓库 11-18 03:55 UTC 起持续 404）
- **来源**：GitHub 仓库状态（一手观测）、onnx/onnx issue #8842（一手记录）；Stack Futures、codingislove、DEV、Habr 等多方报道；Hacker News（讨论）
- **核心内容**：github.com/microsoft/onnxruntime（约 22.3k stars、MIT 许可的跨平台推理引擎）自 11-17 深夜起返回 404，随后 onnxruntime-genai、onnxruntime-extensions、onnxruntime-github-actions 与 microsoft/agent-framework 相继下线。PyPI/NuGet/npm 上的发行包仍可安装（11-13 发布的 v1.32.0 正常），但源码构建、release 附件下载与 issue 追踪全部中断，直接引用 GitHub 链接的 CI/CD 流水线大面积报错。同日稍早，微软 agent-framework 的 PyPI 包被发现两个含凭据窃取器的恶意版本（发布后已移除）；社区普遍猜测仓库下线是供应链入侵响应的一部分，但截至发稿微软与 GitHub 均未发布任何官方解释。onnx/onnx issue #8842 正在跟踪缺失清单，社区临时改用 Intel fork 等镜像续命。
- **背景/影响**：22k 星的根基础设施项目"无声消失"且无通告，暴露了对 GitHub 单点的深层依赖（源码、发布物、issue 一体消失）；若确因 PyPI 投毒触发应急响应，"包仓库投毒 → 代码托管整体下线"将成为供应链安全的新范式案例。原因未明，本条以可观测事实为准，后续以官方说明修正。
